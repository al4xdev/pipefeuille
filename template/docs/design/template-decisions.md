# Decisions that already come with the template

This document explains **why** each template rule exists. It compiles the decision record made while the template was being built, rewritten as current state: the rule, the reason, what was measured, the gate that protects it and what that gate does **not** prove.

Who should read: every agent before the first wave (see [reading-order.md](reading-order.md)), and any agent tempted to "simplify" a rule. If a rule here gets in the way of the new project, do not work around it and do not record it as decided: write a `Status: proposed` entry in the project's [`architecture-log.md`](architecture-log.md) with the measured cost and stop until the owner approves in their own words, or under a delegation the owner wrote, with a critic ([AGENTS.md → Deviations](../../AGENTS.md#deviations-owner-decision), D8).

How to read each entry:

- **Rule:** what the code does today.
- **Why:** the problem the rule solves, almost always actually seen.
- **Gate:** the test or the configuration that fails if the rule is broken.
- **Does not prove:** what remains human or orchestrator-model review.

The complete guide is in [vertical-pipelines.md](vertical-pipelines.md); the names, in [vocabulary.md](vocabulary.md).

## A. Shape of the tree

### A1. Four files in every folder, no `__init__.py`, reading starts at `run.py`

- **Rule:** every `backend_logic` package has exactly `contracts.py`, `container.py`, `pipeline.py` and `run.py`, and no other module. There is no `__init__.py` anywhere in `backend_logic/` or `http_adapter/`: folders are namespace packages (PEP 420). What a package does is the docstring of its `def run` (E1). All reading starts at `run.py`/`def run`. The only exceptions are the two forms of A5, `_shared/` (no module) and the grouping inside it (only `contracts.py`), and the two folder kinds of declarations of A6, which hold no Python at all.
- **Why:**
  - In an earlier version, `backend_logic/` had no `run.py`; `codec/jsonvalue.py`, `storage/files.py` and `storage/locks.py` were loose modules with names that do not say what they do; `notes/` had `contracts.py` without `run`. The owner, reading, did not know where to start. With fixed names, whoever does not know the domain still knows where the package runs, what it holds and what it exchanges.
  - The `__init__.py` held a one-line docstring that the `run` docstring would repeat once E1 put the description there. Two places for one sentence drift apart; and an `__init__.py` is also the one module that runs on import, where startup code tends to land.
- **Measured:** on a copy with every `__init__.py` removed, pytest passed except the shape gate, and `lazy from .contracts import …` resolved as namespace packages. mypy stopped at once ("Duplicate module named `container`"); with `explicit_package_bases = true`, `backend_logic` and `http_adapter` were clean and the only errors were in `tests/`, because test modules are now named from the root (`tests.gates.test_config`). `mypy_path = ["tests/support"]` keeps the support modules named by file (`wire_client`, `deviations`), as on the pytest `pythonpath`.
- **Gate:** `tests/gates/test_style.py::test_every_folder_has_the_files_its_kind_requires` (with self-test in `::test_shape_scanner_reports_every_kind`, which includes a package with the retired `__init__.py`), `::test_no_module_outside_the_mandatory_names`, `::test_no_package_has_an_init_module`; `tests/gates/test_architecture.py::test_run_modules_contain_a_real_run_definition`; `tests/gates/test_config.py::test_mypy_gate_keeps_any_out_of_expressions_everywhere` requires `explicit_package_bases` and the exact `mypy_path`.
- **Does not prove:** that the content of each file is in the right file (a domain type forgotten in `pipeline.py`, for example). Nor that no other folder of the same name sits on `sys.path`: namespace packages merge silently, which is why `pythonpath` and `mypy_path` are fixed.

### A2. Climb by families: the root is the single door

- **Rule:** a family declares `type <Family>Request = A | B` and `<Family>Response` in `contracts.py` and dispatches with `match`/`assert_never` in `run.py`. `backend_logic/` is a family, and every ancestor of a family is too. Children of a process are steps, not cases. The HTTP adapter enters only through `backend_logic/run.py`.
- **Why:** any use case is found by descending `match` by `match` from a single file. Named requests (`SaveNote`, `PrepareResources`) replaced generic `Input`/`Output` because the request name is readable outside the package.
- **Gate:** `tests/gates/test_style.py::test_every_family_run_dispatches_by_typed_use_case` (family without `match` or family under a process); `tests/example/test_backend_run.py::test_each_family_is_reached_from_the_root`; `tests/gates/test_architecture.py::test_http_enters_only_through_the_root_run`; mypy `exhaustive-match`.
- **Does not prove:** exhaustiveness beyond what `assert_never` and mypy guarantee.

### A3. `@overload` only at the root; the exact product comes from the process

- **Rule:** only `backend_logic/run.py` has `@overload` per use case (the public "menu"). Intermediate families return the union. Whoever needs an exact product imports the **process's** `run` (`lazy from backend_logic.notes._shared.storage.lock import run as locking`); a family's `run` is only imported by the parent's `pipeline.py`.
- **Why:** mypy does not check an overload against each `case`. Measured on a copy: with `run(EncodeValue) -> int` and a body returning `str`, the `run.py` of the family that then dispatched JSON passed clean and only the callers broke. Without any overload, a family's `materialize()` only promises the union, and callers would need `isinstance`. One block at the root, covered by a test that calls each case, leaves a single promise.
- **Gate:** `tests/gates/test_style.py::test_only_the_root_declares_overloads_and_only_parents_call_a_family` (verified against the old version: it listed the 4 families with overload and the 6 shortcuts).
- **Does not prove:** that the root's overloads tell the truth; that is checked only by `tests/example/test_backend_run.py`.
- **Consequence that led to A5:** with this rule, the `storage` and `json` families were left without a caller: everyone called the operation directly. A family that nobody calls is dead code that looks like a door. A5 solved this by taking the mechanisms out of the family role.

### A4. A mechanism is one package per operation

- **Rule:** `_shared/json/{decode,encode}` + `_shared/json/_shared/validate` and `notes/_shared/storage/{read,write,scan,lock}` + `storage/_shared/path`, each operation with the four files. Never `files.py`, `utils.py`, `jsonvalue.py`.
- **Why:** same reason as A1; and a folder name such as `storage/write/` says what happens without opening the file. Alternative discarded: tolerating loose modules for mechanisms.
- **Gate:** the same as A1.
- **Does not prove:** that the split into operations is the best one for another mechanism; that is design.

### A5. Depth says who uses it; shared lives in `_shared/`

- **Rule:** a package used by a single consumer stays inside it. A package used by two or more neighbours, that has its own contract and is **not a use case**, lives in the `_shared/` of their nearest common ancestor. The `_shared/` folder exists even when it holds a single package. `_shared/` is never a family, is private to the parent and has no module of its own; a grouping inside it (`json/`, `storage/`) has only `contracts.py`, without `run`. Importing only the types of a package counts as use. Guide §2.
- **Why:**
  - The name authority lived only in `save.validate_name`. `save/decode` accepted `"../escaped"` and `list` returned raw stems as `str`. The policy was duplicable, and its place in the tree did not say who used it. A rejected name coming from disk is corruption (`ValueError`, 500), not a client error (`invalid_name`, 422).
  - Later, with the shared package next to the use cases (`notes/name/` beside `list/` and `save/`), the tree did not distinguish infrastructure from use case. And the mechanism families (A3) had no caller.
  - The owner decided to name the shared and tested the fear of "hundreds of `_shared`" against a 201-package codebase built in this style:
    - counting any import, 16 of 76 levels would gain `_shared/`; counting only `run` calls, 10;
    - most would end up with 1 or 2 packages;
    - the big false positive was domain using domain (6 of 10 root packages), hence the condition "is not a use case".
  - `_shared/` always, and not "only with two or more", because an unconditional rule is easier for implementers and the second shared package does not change the path of the first.
  - Alternatives discarded: `utils/` at the root (grows without an owner); shared loose beside the use cases (unreadable); mechanism as a family (no caller).
- **Applied to the template:**
  - `roles/summarizer` uses `NoteName`, so the name moved up to `backend_logic/_shared/note_name/`.
  - Only `notes` touches disk, so `storage/` moved down to `notes/_shared/storage/`, and the lifetime resources became `notes/prepare/`'s (formerly `runtime/application/`).
  - `PrepareResources` is now a case of the `notes` family.
- **Gate:**
  - `tests/gates/test_style.py::test_shared_packages_sit_at_the_nearest_common_parent`, which checks:
    - two consumers per package in `_shared/`;
    - `_shared/` private to the parent;
    - shared outside `_shared/` is flagged.
  - The self-test `::test_placement_scanner_reports_every_rule` covers this gate. Run against the earlier tree, it flagged `json/validate`, `notes/name` and `storage/path`.
  - `::test_every_family_run_dispatches_by_typed_use_case` fails a family or grouping with `<Family>Request` inside `_shared/`.
  - Behaviour: `tests/example/test_notes_name.py`, `tests/example/test_notes_save.py::test_stored_name_passes_the_same_authority_as_save_input`, `tests/example/test_notes_list.py::test_misnamed_file_fails_the_listing_instead_of_disappearing`.
- **Does not prove:**
  - That the package really has its own contract, and is not a promoted convenience function. That is the test "if two copies diverged, would it be a bug?", which stays with the orchestrator's review.
  - That a use case is in the right family.

### A6. Declarations: a catalogue of apps, data bound to a use case

- **Rule:** besides packages, `_shared/` and groupings, the tree may hold declarations, in two folder kinds that hold no Python:
  - **catalogue** (kind `apps`): a folder named `apps/` directly inside a package, the holder, whose mechanism the apps configure.
    - It holds only app folders, at least one, each named `[a-z][a-z0-9_]*`, and no file.
    - `apps` is a reserved name: a folder of that name is always a catalogue, never a package.
    - The holder may be a package inside `_shared/` (a shared mechanism), but the catalogue never sits directly in the `_shared/` folder, in a grouping, or in an app. A path has exactly one `apps/`.
  - **app** (kind `app`): `<holder>/apps/<name>/`. It holds exactly one regular file, `app.toml`, and nothing else: no other file, no folder, no Python.
  - Nothing below a catalogue is skipped, unlike everywhere else: a `__pycache__/`, a symlink (to a folder or to `app.toml`) or a FIFO there is a violation.
  - No entry named `app.toml`, of any type, sits anywhere else under `backend_logic/`: not beside a `run.py`, not in a `__pycache__/`, not below a second `apps/`.
  - The file is a closed subset of TOML read by `tests/support/declarations.py` with the standard library only.
    - **Head:** exactly `use_case` and `summary`, each once, both strings. The template's gates read them and hold them to the code.
    - **`[settings]`:** an optional table for the project's own keys, each `key = "text"` or `key = 123` (decimal). The reader returns the values typed (`str | int`). The gates check only their form; **each project key is held to the code by a project-owned test in `tests/<family>/`**.
    - **Lines:** comment lines, blank lines, the header `[settings]`, and `key = value` lines with a lowercase key and exactly one space around `=`. A string has no `"` or `\`. An integer has at most 18 digits and is never `-0`. No line holds a character of the Unicode categories `Cc` (tab included), `Cf`, `Zl`, `Zp`, `Co` or `Cs`. Only LF or CRLF end a line. A file that is not UTF-8 or not a regular file is a problem, never an exception.
    - **Fails:** an unknown, repeated or missing head key; a head key under `[settings]`; a repeated key or header; another or nested table; a float, boolean or array; an inline comment; an empty `[settings]`.
    - Reading is two checks: a lexical check of every line against the subset, then `tomllib.loads` through the typed stub `tests/support/tomllib.pyi` (values `object`, narrowed with `isinstance`). Every accepted file is valid TOML, read with TOML's meaning.
  - `use_case` is a package path under `backend_logic/` (`notes/list`) naming a **use case**. That is a **process** with a `run.py` that its parent family dispatches by a `case`, outside every `_shared/`; never a family. It sits strictly inside the holder or calls the holder through one or more calls, and it is never the holder itself.
  - A new head key, table, kind or file name is a change to the pipefeuille (RUNBOOK, task C); a project never edits the reader or the gates to add one. A project key needs no change here: it goes under `[settings]`, with its test.
  - Template example: `backend_logic/notes/apps/list_notes/app.toml` binds `notes/list`, with the project key `route = "/notes"`. Guide §2 ("Declarations") and §2.2.
- **Why:**
  - In a project born from this template, a mechanism served some use cases to external callers, and which ones it served was a literal table in the HTTP adapter. The template had no place for data in the tree: every folder was `_shared/`, a grouping or a package of exactly four files. The first placement, a declaration beside each bound use case's `run.py`, scattered those bindings through the families, so reviewing all of them meant walking the whole tree. The owner moved them into one catalogue inside the package of the mechanism they configure, one folder per binding, and then made the shape a generic rule of the template (2026-11-17, "Sim, regra genérica").
  - Data and not code: a binding is a fact a reviewer reads in a list, not a composition; one folder per app gives one diff per app.
  - A closed schema, read strictly, for the reason of C1 and D1: the readers and writers are language models, and an open format invites improvised keys. YAML needs a library; TOML is in the standard library.
  - A head and one table for project keys. The first version closed the file at the two head keys, which could not host the real case it generalizes. That case's declaration also carried a route, a byte limit, an hourly quota and a client scope, held to the code by a test of that project. The template's gates cannot know what such a key means. So the gates hold the head; the table keeps every other key closed in form (one table, strings or decimal integers, no nesting) and leaves its meaning to a project-owned test, as the originating project already did.
  - `tomllib` behind a lexical check, not a hand parser. The first version parsed the subset by hand, because typeshed types `tomllib.loads` as `dict[str, Any]`. Since the stub `tests/support/tomllib.pyi` (C2) types the values as `object`, `tomllib` can be used under `disallow_any_expr`. It is as strict and simpler: the lexical check keeps the subset (one pattern per line, no state), and `tomllib` brings what a hand parser had to carry itself (repeated keys and headers, which keys belong to which table, the value of `1_000`). Every accepted file has passed TOML's own parser, not a reimplementation of it.
  - The binding must reach the holder: the apps configure the holder's mechanism for that use case, so a use case that never reaches it would be a binding that nothing honours. The originating project checked that its use case reached the mechanism's code through its imports; the generic form is the graph's call reachability.
  - A critic on another model attacked the first two versions and verified six holes, each fixed with a self-test:
    - a family bound as `use_case` (and a holder binding itself);
    - a `__pycache__/` inside a catalogue or an app, which every scanner skipped, holding arbitrary files;
    - a symlinked app folder hiding a malformed `app.toml`, and a broken symlink or FIFO named `app.toml` passing as "not a file";
    - a second `apps/` inside an app, whose declaration dropped silently from the graph;
    - unchecked app names;
    - invisible characters (C1 controls, U+2028, a bidi override, a zero-width space), `-0`, a 5000-digit integer and a non-UTF-8 file. The last two raised uncaught exceptions.
  - A holder inside `_shared/` stays allowed, against that critic's proposal to forbid any `_shared` part. The case this rule generalizes is exactly a shared mechanism (`_shared/upload/`) whose catalogue binds use cases of two families. Forbidding it would leave the rule unable to host its own origin. What stays forbidden is a catalogue directly in the `_shared/` folder, which is a shelf, not a package.
  - Self-binding is refused: a declaration names who uses the mechanism, and a package that only "binds itself" says nothing the tree does not already say.
  - Alternatives discarded:
    - the declaration beside the use case's `run.py`, which scatters the bindings;
    - a top-level tree of declarations, which separates the data from the mechanism that reads it;
    - "the graph skips any folder with no Python below it", which is silent: a misnamed data folder would vanish from the map instead of failing. The template names the two kinds, so the graph and the shape gate both know them;
    - an open head, because the gate cannot hold a key it does not know to the code;
    - an open `[settings]` (any TOML), because nested tables, arrays and floats leave a project's test more shapes to check and the reader more `object`s to narrow.
- **Measured:**
  - In the project where the need appeared: one catalogue with two apps, each binding a use case of a different family to the same mechanism.
  - On a copy of the template, each of four mutations turned the gates red, and reverting it made them green again (145 passed):
    - a `helper.py` inside the app folder failed `test_style.py::test_every_folder_has_the_files_its_kind_requires` and `::test_no_module_outside_the_mandatory_names`;
    - a second file (`README.md`) in the app failed `::test_every_folder_has_the_files_its_kind_requires`;
    - `app.toml` copied beside `notes/list/run.py` failed `test_declarations.py::test_every_declaration_sits_in_a_catalogue`;
    - `use_case = "notes/listing"` failed `test_declarations.py::test_every_app_binds_a_use_case_of_its_holder` and both tests of `tests/example/test_notes_apps.py`.
  - In the last two mutations, `uv run python tests/support/architecture.py` printed the problem as `declaration: …` and exited 1.
  - The critic's repros, replayed on a copy of the template after the fixes (193 passed clean), each turned the gates red:
    - `use_case = "notes"` and `use_case = "roles"` failed `test_declarations.py::test_every_app_binds_a_use_case_of_its_holder`;
    - `__pycache__/` in `apps/` and in the app, a symlinked app folder, and `BAD NAME!` failed `test_style.py::test_every_folder_has_the_files_its_kind_requires`;
    - a broken-symlink `app.toml` beside `notes/list/run.py` failed `::test_every_declaration_sits_in_a_catalogue`;
    - a FIFO `app.toml` failed `::test_every_declaration_is_well_formed` ("not a regular file") and the shape gate;
    - `apps/` nested in an app failed `::test_every_declaration_sits_in_a_catalogue` and the shape gate;
    - `apps/` directly in `_shared/` failed `::test_every_app_binds_a_use_case_of_its_holder` and the shape gate;
    - U+0085, U+202E, U+200B, `-0`, a 5000-digit integer and a Latin-1 byte each failed `::test_every_declaration_is_well_formed`, as a problem, not an exception.
  - `apps/` in the shared package `_shared/note_name/` binding `notes/list` passes every template gate, by design (above). Only the example's pin of the catalogue fails.
  - After `[settings]` and the switch to `tomllib`, on a copy (154 passed before and after each mutation), these mutations of the example also turned the gates red:
    - `route = "/note"` failed `tests/example/test_notes_apps.py::test_the_declared_route_serves_the_bound_use_case` and `::test_the_notes_catalogue_is_the_apps_there_are`;
    - `flag = true`, a repeated `route` and a `[settings.deep]` header each failed `test_declarations.py::test_every_declaration_is_well_formed`;
    - the reader's integer pattern loosened to `-?[0-9_]+` failed `::test_declaration_reader_is_strict` and `::test_lexical_subset_never_accepts_what_tomllib_rejects`.
- **Gate:**
  - Shape: `tests/gates/test_style.py::test_every_folder_has_the_files_its_kind_requires` (kinds `apps` and `app`), with the self-test `::test_shape_scanner_reports_every_declaration_rule`. That self-test covers Python in an app, a second file, a folder in an app, a file in a catalogue, a catalogue in `_shared/` and an empty catalogue. `::test_shape_scanner_skips_nothing_in_data_folders` covers a `__pycache__/` in a catalogue and in an app, a symlinked app folder, a symlinked and a FIFO `app.toml`, misnamed apps and a catalogue inside an app.
  - Content: `tests/gates/test_declarations.py::test_every_declaration_sits_in_a_catalogue`, `::test_every_declaration_is_well_formed` and `::test_every_app_binds_a_use_case_of_its_holder`, with two self-tests:
    - `::test_declaration_reader_is_strict` covers a good file with `[settings]` (typed values), CRLF, every lexical failure (another or nested table, boolean, float, array, leading zero, `-0`, 19 and 4301 digits, inline comment, spacing, escape, dotted key), every hidden character (vertical tab, C0 and C1 controls, U+2028, a bidi override, a zero-width space, a BOM, a tab, a lone CR), the `tomllib` failures (repeated key, repeated header), and the structure failures (a project key in the head, a non-string head value, a head key under `[settings]`, an empty `[settings]`, a `_shared` path, an empty summary);
    - `::test_lexical_subset_never_accepts_what_tomllib_rejects` is the differential check. On about 40 000 seeded near-miss lines, every line the lexical check accepts must parse with `tomllib` alone, after a head and under `[settings]`, and keep its value;
    - `::test_declaration_scanners_report_every_misplacement_and_broken_binding` covers a declaration beside a `run.py`, one too deep, a missing key, a missing package, a step of a process and a use case that never reaches the holder. It also checks that no node is made below a catalogue.
    - `::test_declaration_scanners_refuse_hostile_entries_and_bindings` covers a declaration in a `__pycache__/`, below a nested `apps/`, as a FIFO beside a `run.py` and as a broken symlink (all misplaced); a FIFO and a symlink in place, and a Latin-1 file (problems, not exceptions); a catalogue directly in `_shared/`; a family as `use_case`; and the holder binding itself. A well-bound app inside the holder and one in a shared package pass.
  - Map: `tests/support/architecture.py` (`binding_problems`, `declaration_problems`; the apps on `Node.apps`).
  - Example: `tests/example/test_notes_apps.py` pins the notes catalogue and holds its project key: `::test_the_declared_route_serves_the_bound_use_case`.
- **Does not prove:**
  - That anything reads a catalogue at run time: in the template nothing does, and in a project the holder's own reader and its tests carry that, including whether that reader is as strict as the gate's.
  - That the `summary` tells the truth, or that a fact belongs in a declaration rather than in code: that is review.
  - Anything about the meaning of a `[settings]` key, nor that every key has a test: a project key that no project test reads passes every template gate. Pinning the whole `Declaration` in a project test, as `tests/example/test_notes_apps.py` does, makes a new key fail until someone looks at it.
  - Anything about other files: only `app.toml` and the shape of the two kinds are checked. A data file with another name inside a package is not reported, because the shape gate looks only at `.py` names in packages.
  - Reachability through anything but the `<alias>.run(...)` calls the graph sees (E1).
  - Visible look-alikes (a Cyrillic `а` in a `summary`) and unassigned code points: only the listed categories are refused, because unassigned ones depend on the Python version's Unicode tables.
  - Symlinked folders outside a catalogue: `rglob` does not follow them, so an `app.toml` behind one is not seen.

## B. Reading the code

### B1. `run.py` outside the formatter

- **Rule:** `[tool.ruff.format] exclude = ["backend_logic/**/run.py", "docs/**/*.md"]` with `force-exclude = true`. `# fmt: off`/`# fmt: on` forbidden in `backend_logic`. The linter still applies to `run.py`.
- **Why:** the increasing indentation of the chain in `run` communicates sequence, and the formatter would flatten it. Before, each `run.py` repeated `# fmt: off`, which was noise and easy to forget in a new package. Without `force-exclude`, an editor or agent that passes the file path would ignore the exclude. The `.md` files are excluded because ruff formats Python blocks inside Markdown, and the guide quotes `run.py` compositions.
- **Gate:** `tests/gates/test_config.py::test_run_composition_is_left_to_the_author_not_the_formatter`, `tests/gates/test_style.py::test_run_composition_has_no_formatter_escapes`.
- **Does not prove:** that the hand-written `run.py` is well indented.

### B2. `await` on its own line

- **Rule:** an async step is `await pipe.x()` on its own line; the template does not chain after the `await`.
- **Why:** chaining is valid Python, but from the second async step on it becomes `(await (await pipe.a()).b()).c()` and the suspension point disappears in the parentheses. On its own line, the `await` sits at the column of the `async with` and the `if`s, where the reader looks for what can be interrupted.
- **Gate:** none mechanical; review.
- **Does not prove:** —

### B3. Real parallelism with `TaskGroup` (`roles/digest/`)

- **Rule:** parallel is `asyncio.TaskGroup` calling the `run`s of sibling packages, visible in `run`. Budget and preconditions are validated before any paid call; integration happens after the barrier, in request order. The first failure cancels the rest; there is never a partial result.
- **Why:** the guide prescribed the pattern without demonstrating it. Alternative discarded: `gather(return_exceptions=True)`, which would return a partial digest without a contract for that.
- **Gate:** `tests/example/test_roles_digest.py`. The concurrency test hangs if the calls are sequential (the first note's fake waits for the second to finish, under `asyncio.timeout(1)`). Verified by mutation: sequential loop, partial `gather` and removal of `validate_notes` made the tests fail.
- **Does not prove:** concurrency limit against a real provider (there is no semaphore) nor aggregate cost in tokens.

## C. Typing

### C1. `Literal` for closed sets, `NewType` for numbers with a role

- **Rule:** `NoteConflictCode`, `NoteValidationCode`, `WritePhase`, `Language` are `Literal`; `Revision` is `NewType`; `NoteView.title` is `NoteName`.
- **Why:** the frontier model types the contracts and smaller models fill in the methods; everything the type does not close is room to break the contract without the gate seeing it. When `Revision` was wired in, mypy pointed to 7 places in the tests where a raw `int` became a revision.
- **Kept on purpose:** budgets (`output_tokens`, `max_*`) as `int` with a name on the parameter (`TokenBudget(256)` worsens the reading of `run`); `SelectLock.kind` as `str` (the mechanism does not depend on the domain); `NoteDocument` without `TypedDict` (it would not be assignable to `JsonValue`); free texts and not-yet-admitted input (`SaveNote.name`).
- **Gate:** mypy; `tests/gates/test_style.py::test_error_codes_and_phases_are_closed_sets` (forbids `code`/`phase` as `str`) and the scanner's self-test.
- **Does not prove:** that other closed sets were discovered; the gate only looks at those two names.

### C2. Type first: a library's `Any` is typed before any exemption

- **Rule:** strict mypy with `disallow_any_explicit`, `disallow_any_unimported`, `disallow_any_expr` (whole project, tests included), `warn_unreachable`, `strict_bytes` and the extra codes of `pyproject.toml`. The template exempts **no** module: `pyproject.toml` has no `[[tool.mypy.overrides]]`. A library that hands over `Any` (or ships no types) is typed, in this order of preference, before an exemption may even be proposed:
  1. **Annotate and narrow.** mypy does not report an `Any` expression assigned directly to an explicitly annotated variable. Annotate it as `object` (never as the type you hope for) and narrow with `isinstance` or a strict decoder: `value: object = json.loads(...)` in `backend_logic/_shared/json/decode/pipeline.py`. Pass an annotated local to a library parameter typed with `Any` (`body: JsonValue = {...}` before `JSONResponse(body)`; `options: dict[str, str | int] = {...}` for a parameter typed `dict[str, Any]`). `isinstance(x, dict)` narrows to `dict[Any, Any]`; rebuild with typed keys instead (`table` in `tests/gates/test_config.py`).
  2. **Specialise the generics.** A generic class used bare becomes `X[Any]`; spell its type arguments (a connection pool generic over its connection type is built as `Pool[Connection[Row]]`, not `Pool`).
  3. **Avoid the `Any`-typed surface of the API.** Use the typed call the library also offers: FastAPI routes through `router.add_api_route(path, function, methods=[...])` (its decorators are typed with `Any`); `responses=` maps as annotated module constants; a typed holder of ours instead of `app.state` (`http_adapter/lifetime.py::ResourceSlot`); a typed library instead of an untyped helper (`tests/support/wire_client.py` drives the app through `httpx.ASGITransport` and the ASGI lifespan protocol, because Starlette's `TestClient` is typed against a package the template does not install).
  4. **Write a stub.** For a library without types, or whose types carry `Any`, a `.pyi` under `tests/support/` (on `mypy_path`, so it takes precedence over the library's own types) declares the part the project uses, with `object` wherever the library promises nothing. `tests/support/tomllib.pyi` is the template's: `loads(...) -> dict[str, object]` instead of typeshed's `dict[str, Any]`. A package keeps its path (`tests/support/<package>/<module>.pyi`). Every stub is checked against the installed library (D9).
  5. **Last resort: a `mypy:<module>` exemption,** proposed under D8 with the measured error count of that module and the recipes above that were tried, and only after the owner approves. It is one `[[tool.mypy.overrides]]` that lifts only `disallow_any_expr` for a boundary module that narrows before returning.
- **Why:** the same as C1. In a project born from this template, three libraries handed over `Any`: an async database pool, the HTTP framework, and a cloud storage client with no types. The agent proposed one exemption per boundary module (3 and 13 `disallow_any_expr` errors) and had loaded the libraries by name through `importlib` (D9). The owner rejected both, and every library was typed with the recipes above. The template itself then carried three exemptions that turned out to be unnecessary (measured below).
- **Measured:** on the template, with every override removed: `backend_logic._shared.json.decode.*` 0 errors (recipe 1 already applied); `tests.gates.test_config` 8 errors (4 from `tomllib.loads`, removed by the stub; 4 from `isinstance(x, dict)`, removed by `table`); `wire_client` 4 errors (every response of `TestClient`, removed by `httpx.ASGITransport`). Removed: 3 of 3; kept: 0. In the project above, the same recipes removed 3 errors (the pool), 13 errors (the framework) and every call site of `importlib`, with no exemption left.
- **Gate:** `tests/gates/test_config.py::test_mypy_gate_keeps_any_out_of_expressions_everywhere` fails if mypy loses any strict flag or extra error code, if an override does anything but lift `disallow_any_expr`, or if it exempts a module that no owner-approved `mypy:<module>` entry lists (D8): the template has no exemption of its own left. `::test_ruff_rules_are_never_switched_off` fails on a dropped rule, a longer line or any `ignore`/`per-file-ignores`. mypy itself rejects `Any` written in a stub (`explicit-any`). Stubs: `tests/gates/test_boundaries.py::test_every_stub_matches_the_installed_library` (D9).
- **Does not prove:** that an annotation tells the truth. `x: int = library_call()` turns `Any` into `int` without a word from mypy, exactly like a `cast`; so does a stub that declares a narrower type than the library returns. The rule is to annotate `object` and narrow, and the review of the diff checks it. Nor that a new library will come typed.
- The template's only escape hatches are the `cast(JsonValue, ...)` in `_shared/json/_shared/validate/pipeline.py`, after a full recursive check, and the `# type: ignore[call-overload, misc]`s in `tests/example/test_backend_run.py`, which calls `run` wrongly on purpose to exercise the runtime guard. `tests/gates/test_deviations.py` allows them by path suffix and nothing else without an approved `suppress:<file>`.

### C3. Python 3.15 and every top-level import `lazy`

- **Rule:** `requires-python = ">=3.15"`; every top-level import in `backend_logic` and `http_adapter` is `lazy` (PEP 810). An exception is an owner-approved `eager:<module>` entry in `architecture-log.md` (D8); the gate file is not edited. `tests/` stays eager.
- **Why:** owner's choice. Importing the root does not load the whole tree: after importing `backend_logic.run`, `notes._shared.storage.write.pipeline` and `roles.digest.run` are not in `sys.modules`.
- **Measured:** CPython 3.15.2 resolved the 37 dependencies. `pyyaml` (via `uvicorn[standard]`) has no cp315 wheel and was compiled without the C extension: it works, slower. The fallback (all `lazy` removed) passed mypy and the tests outside `test_style`. In this build, `-X lazy_imports` has no option to turn it off: the fallback is editing the code.
- **Gate:** `tests/gates/test_style.py::test_every_top_level_import_is_lazy` and its self-test.
- **Does not prove:** that every import path resolves. An import error appears on first use, so each `run` needs to be exercised by some test.

## D. Boundaries and effects

### D1. One strict JSON for the three ingestion boundaries

- **Rule:** `_shared/json/decode` is the only JSON reading policy (duplicates, `NaN`/`Infinity`, lone surrogates, depth → `ValueError`), used by storage, by the LLM role and by the HTTP edge. `_shared/json/encode` refuses what the decode would refuse. The HTTP edge reaches it through the root: `DecodeText` and `EncodeValue` are root cases that call the operation directly, without a JSON family.
- **Why:** a critical review reproduced `{"body": "\ud800"}` passing through the HTTP edge and becoming a 500 on write; `"[" * 2000` escaped the summarizer as `RecursionError`; the edge accepted duplicate keys. The policy was duplicated and incomplete.
- **Gate:** `tests/mechanisms/test_storage_json.py`, `tests/example/test_http_notes.py::test_malformed_wire_body_is_rejected_before_the_logical_run`, `tests/example/test_summarizer.py::test_contract_violations_reject_without_a_second_call`.
- **Does not prove:** body size limit nor parsing cost.

### D2. HTTP edge without pydantic; resources in the `lifespan`

- **Rule:** the HTTP adapter reads bytes, decodes through the single door (`backend.run(DecodeText(...))`) and checks the wire shape in a dataclass. Store, locks and clock are born in the `lifespan` through `backend.run(PrepareResources(...))`; constructing the app does not touch disk.
- **Why:** `pydantic.BaseModel` models introduce `Any` and fail `disallow_any_explicit`. Pydantic at the edge would loosen a flag that no log token opens: it is a change to the pipefeuille by its owner, never a project deviation; in `backend_logic`, never.
- **Gate:** `tests/example/test_http_notes.py::test_app_construction_touches_no_disk_until_the_lifespan_starts`, `tests/gates/test_architecture.py::test_logic_does_not_import_http`.
- **Does not prove:** transport security, authentication or body limits.
- **Name:** the package is `http_adapter/`, not `*_frontend`. The door is `backend_logic/run.py`; this package is an adapter that goes through it, and it has no UI. A second transport gets a sibling with the same suffix (`cli_adapter/`) and the same rules; the gates' `HTTP`/`ADAPTER` constants, and `CODE` in `tests/gates/test_boundaries.py`, must then list it too.

### D3. Validate rejects, never fixes; path confined per segment

- **Rule:** `validate_*` does not `.strip()` nor normalize. A note name is an explicit ASCII set. `storage/path` rejects `""`, `"."`, `"notes/."`, `\`, NUL, absolutes and `..` instead of normalizing them. A document whose `name` does not match the path is not accepted as a predecessor.
- **Why:** `validate_name` did `.strip()` and accepted `"²½"` via `str.isalnum()`; the path accepted `"notes/."`; `notes/a.json` with `name: "b"` was accepted.
- **Gate:** `tests/mechanisms/test_storage_json.py::test_path_rejects_instead_of_normalizing`, `tests/example/test_notes_name.py::test_invalid_names_are_rejected_never_corrected`, `tests/example/test_notes_save.py::test_misfiled_document_is_not_accepted_as_predecessor`.
- **Does not prove:** behaviour with symlinks nor with multiple processes.

### D4. Publication with receipt; failure before and after commit

- **Rule:** `storage/write` publishes with a temporary file in the same directory → flush → fsync → atomic replace → directory fsync, and returns `WriteReceipt` (`NOT_PUBLISHED`, `PUBLISHED_NOT_DURABLE`, `DURABLE`) with the published size. A failure of the publication itself propagates `AtomicWriteError` with the receipt; a failure **after** it becomes `NoteResultError` with the receipt. There is never a hidden retry.
- **Why:** the receipt lost `size_bytes` when the directory fsync failed after the replace; and "failed" without a receipt would lead the caller to rewrite something already published.
- **Gate:** `tests/example/test_notes_save.py::test_directory_fsync_failure_reports_published_bytes`, `::test_failure_after_commit_keeps_the_receipt_and_never_rewrites`, `tests/mechanisms/test_storage_json.py::test_unserializable_value_fails_before_publication`.
- **Does not prove:** real durability on every filesystem; the test simulates the failure.

### D5. Named locks, never evicted, rehearsed with `await` inside

- **Rule:** `storage/lock` returns the same `asyncio.Lock` for the same `(kind, name)` and never removes it. The lock is acquired in `run` (`async with locking.run(SelectLock(...))`), not inside a method.
- **Why:** removing a lock would allow an old waiter and a new lock to overlap. And a test of two concurrent writes does not observe the lock when the steps have no `await`: the old `gather` test only proved "the second creation conflicts", not exclusion.
- **Gate:** `tests/example/test_notes_save.py::test_named_lock_excludes_same_name_and_admits_other_names` (a holder waits inside the lock).
- **Does not prove:** exclusion between processes.

### D6. Style gates have a self-test

- **Rule:** each scanner in `tests/gates/test_style.py`, `tests/gates/test_architecture.py`, `tests/gates/test_boundaries.py` and `tests/gates/test_declarations.py` has a test that runs it against a synthetic violating source.
- **Why:** an import scanner that only read `node.module` passed empty without seeing `from X import a`.
- **Gate:** `test_style_scanner_reports_every_rule`, `test_shape_scanner_reports_every_kind`, `test_placement_scanner_reports_every_rule`, `test_closed_name_scanner_reports_bare_str`, `test_eager_import_scanner_reports_only_top_level_eager_imports`, `test_internal_import_scanner_sees_every_import_form`, `test_log_reader_grants_only_owner_approved_entries`, `test_log_reader_grants_delegated_entries_only_with_quote_and_critic`, `test_log_reader_voids_hidden_repeated_or_malformed_lines`, `test_template_rule_reach_sees_paths_and_wider_patterns`, `test_fence_and_heading_readers_follow_commonmark`, `test_support_reader_follows_every_import_form`, `test_naming_reader_reports_missing_and_extra_names`, `test_escape_hatch_scanner_ignores_strings`, `test_collection_hook_scanner_reports_every_hook`, `test_graph_scanner_reports_every_violation`, `test_docstring_parser_keeps_notes_and_continuations`, `test_loader_scanner_sees_every_form`, `test_loader_audit_finds_every_caller_of_the_import_machinery`, `test_parallel_config_scanner_allows_only_the_harness_server`, `test_third_party_scanner_sees_every_import_form`, `test_dependency_reader_grants_only_what_is_declared`, `test_stub_checker_reports_every_drift`, `test_shape_scanner_reports_every_declaration_rule`, `test_declaration_reader_is_strict`, `test_lexical_subset_never_accepts_what_tomllib_rejects`, `test_declaration_scanners_report_every_misplacement_and_broken_binding`, `test_the_synthetic_tree_is_clean_and_reads_whole`, `test_each_python_reader_gives_the_verdict_the_case_pins`, `test_shape_scanner_skips_nothing_in_data_folders`, `test_declaration_scanners_refuse_hostile_entries_and_bindings`.
- **Does not prove:** semantics. A style gate does not know whether a docstring tells the truth nor whether a `validate_*` fixes in secret.

### D7. Tests are split by lifetime: gates, mechanisms, example

- **Rule:** `tests/gates/` holds the global gates (style, architecture, config) that every project keeps unchanged; they read `backend_logic`/`http_adapter` and, for the agents (E3), `backend_harness/agents`, its captures and its profile, and mention the domain only inside synthetic self-test strings (no gate names the example agent). `tests/mechanisms/` holds the tests of the shipped mechanisms and moves with them. `tests/example/` holds the example-domain tests and is deleted with `notes/` and `roles/`; the example agent goes with them (`backend_harness/agents/summarizer/`, its baseline `backend_harness/tests/baseline/app.summarizer.txt`, its entry in the `AGENTS` table), together with the fake of the agent-runs port, `tests/support/agent_runs.py`, a project helper. A project's own tests go in `tests/<family>/`. Helpers shared by test folders live in `tests/support/`, which is on the pytest `pythonpath`. Test folders have no `__init__.py`.
- **Why:** with every test flat in `tests/`, nothing told a new project which files survive a domain swap; an agent could delete a gate together with the example, or keep example tests that pin the old domain.
- **Measured:** a copy of the template without `tests/example/` gives a clean mypy and 228 passing tests (gates and mechanisms), against 313 with it.
- **Gate:** none mechanical; the measurement above is the evidence. Re-run it after changing a gate.
- **Does not prove:** that a future gate stays domain-free; review a new gate for imports of `notes`/`roles`.

### D8. Deviations: the agent proposes, only the owner approves (directly or by written delegation), the gates read the log

- **Rule:** an exception to a gate exists only as an `architecture-log.md` entry under `## Entries` with `- Status: approved`, `- Exempts:` tokens (`mypy:<module>`, `eager:<module>`, `suppress:<file>`) and one of two approvals:
  - **by the owner:** `- Approved by owner: YYYY-MM-DD "<verbatim words>"`;
  - **by delegation:** the owner delegated approvals to the orchestrator in writing, and the entry carries `- Approved by delegation: YYYY-MM-DD "<the owner's delegation, verbatim>"` and `- Critic: YYYY-MM-DD <critic> checked <what>; verdict: approve`, the review of an independent critic subagent dated on or after the delegation. A delegation covers only what its words name; it cannot widen itself (scope, end, further delegation, a new delegation) and never covers the template's own rules: a delegated token that reaches `tests/gates/`, the template's files in `tests/support/` (`deviations.py`, `architecture.py`, `boundaries.py`, `declarations.py`, `tomllib.pyi`: the one list is `TEMPLATE_SUPPORT_FILES` in `tests/support/deviations.py`) or `pyproject.toml` voids the entry, and so does any delegated `mypy:` pattern (`*`, `?` or `[` anywhere: `backend_logic.*`, `backend_logic.notes.*`, `tests.mechanisms.*`): a delegated token names one module, because a pattern lifts `disallow_any_expr` for a tree, a family or a test folder and for every module added there later, instead of one boundary module (C2), and so loosens `pyproject.toml`; the rules with no token (other `pyproject.toml` loosening, `template-decisions.md`, the owner decisions of `AGENTS.md`) stay outside any delegation. `tests/gates/test_deviations.py::test_template_support_files_are_named_once` holds the list to the gates' imports (every `tests/support` module or stub a gate imports, through other support modules too, is on it, and nothing else) and to the never-edit lists of `AGENTS.md` and the README. A project's own helpers and stubs in `tests/support/` are not on it, so a delegation may open them. An entry has one approval field, never both.

  The reader (`tests/support/deviations.py`) is strict, and its format is in [architecture-log.md → Deviations](architecture-log.md#deviations-proposed-by-the-agent-approved-only-by-the-owner): markup refused rather than modelled (no HTML comment or HTML block start anywhere in the log; inside `## Entries` no code fence, HTML tag, escaped backtick or line of only `=` or `-`; no heading with a closing `#` sequence; only spaces and tabs as whitespace on fence and heading lines), one-line fields at column 0 that appear once and are never empty, ASCII real dates, one quoted span of visible words, `Exempts:` as `none` or a bare token list. Any problem in an entry voids all its tokens, whoever approved it; a problem of the section voids every entry. Whether a delegated `mypy:` pattern reaches the template's rules is decided with mypy's own glob reading (a `*` component spans any number of components) and a shell-style glob, against every module name a template rule file can have (each `tests.gates.<file>`, a gate added later, and each template support file both bare, a stub by the module it replaces (`tomllib`), and as `tests.support.<file>`).

  The agent writes `Status: proposed` with the measured cost and stops (or, under a delegation that covers it, sends it to a critic before approving). `tests/gates/` holds no project exception and is never edited in a project; `pyproject.toml` may be tightened, never loosened beyond an approved `mypy:` override. Protocol in [AGENTS.md → Deviations](../../AGENTS.md#deviations-owner-decision).
- **Why:** the readers of this template are language models, and a model under cost pressure takes the cheapest exit the text leaves open. In a real port, the rules said "a new exception needs an owner decision recorded in `architecture-log.md`". The session left `disallow_any_expr` off, kept `json.loads` outside the single decoder and limited the `lazy` gate to one package, then recorded each choice in the log and reported it afterwards: every step was "recorded", none was approved. Earlier, the exceptions lived inside the gates (`EAGER_IMPORTS`, the list of mypy exemptions), so opening one meant editing a gate, which the agent could do itself. Gate errors are followed more reliably than prose, so the rule now lives in what the gate reads, and the gate's message names the protocol.
  - **Why delegation:** in a later port the owner was away for most decisions and delegated them in the conversation to the orchestrating agent, asking for critic review. With only `Approved by owner`, the log had to put the delegation's words in that field and explain it in a free `Note:` line: the gate could not tell an owner's yes about this entry from a general delegation, nor see whether a critic ran. The alternative, the owner answering every entry, stalls long autonomous work. So delegation is its own field, and the critic is a required, dated field with a closed verdict. The template's own rules stay outside it because a delegated change to a gate would change the rules for every later decision, including the next delegated one.
  - **Why a strict reader:** an independent critic attacked the first version of the delegated reader on a copy and verified six ways to get a grant the rule forbids: `mypy:` patterns that mypy reads as covering a gate (`tests.*.test_style`, `*.test_deviations`, `tests.support.*`) passed the reach check, and an override of `tests.*.test_style` let `json.loads` into a gate with mypy and pytest green; dates in other scripts' digits or impossible dates passed, and beat the chronology check; a blank quote, two quoted spans and an invisible critic name passed; a repeated field silently replaced the first (`Status: proposed` then `approved`; an empty `Approved by delegation:` that turned a delegated entry back into an owner one able to exempt a gate; a `reject` then an `approve`; two verdicts on one line); fences and comments desynchronized from what the page renders (a shorter fence closing a longer one, a comment opened after a closed one on the same line, a comment on an `Exempts` line); and an entry with an unknown token still granted its valid ones. Whatever the reader tolerates is an exit, so it now refuses all of it. A second review showed that modelling the page kept leaking: an escaped backtick opened a real comment that the reader took for a code span, so an entry hidden on the page still granted; a no-break space after a closing fence closed it for the reader but not on the page; a closing `#` sequence changed a heading's text; delegated patterns one level deeper (`backend_logic.notes.*`, `tests.mechanisms.*`) still lifted the gate for a family; and the support-file reader missed imports written from the root (`from tests.support import deviations`). So the reader stopped modelling: it refuses comments, HTML, escaped backticks, setext underlines, closing sequences and odd whitespace, and a delegated `mypy:` token names one module.
- **Measured:** on a copy of the template, three self-granted deviations (an override of `backend_logic.notes.*`, a top-level `import os` with `# type: ignore[misc]`) failed `test_config`, `test_style` and `test_deviations` (3 failed). Adding a `Status: proposed` entry listing all three tokens still gave 3 failed; turning it into `approved` with a dated, quoted owner approval gave all gates green. A second copy tried the exits that switch a gate off without touching it: `tools` added to ruff's `extend-exclude` and mypy's `exclude`, a `cast` in `tools/hack.py`, a root `conftest.py` with `pytest_collection_modifyitems`, and `--ignore=tests/example` in `addopts`. Each failed a gate. A third copy tried a root `mypy.ini` and a `backend_logic/ruff.toml` (both take precedence over `pyproject.toml`), `from typing import cast as narrow` plus a suppression written without spaces in `http_adapter/`, an eager import wrapped in a module-level `try`, and an approved entry hidden inside a multi-line HTML comment together with its override. Each failed a gate (4 failed). For delegation, a copy with a `cast` in `http_adapter/` and one `suppress:` entry: no entry, 1 failed; `Approved by delegation` without `Critic`, 2 failed (`test_architecture_log_is_well_formed`, `test_escape_hatches_only_where_the_owner_approved`); with `Critic: …; verdict: approve`, green; the same entry also listing `suppress:tests/gates/test_style.py`, 2 failed again. After the strict reader, each of the critic's reproductions is a problem and grants nothing (the `tests.*.test_style` override fails `test_architecture_log_is_well_formed` and `test_config`). Seven mutations of the reader each turned at least one self-test red: entries with problems still granting (14 failed), mypy's glob reading dropped (the reach self-test, through `tests.*.gates.test_style`), a fence closed by any run of its character (2 failed), repeated fields allowed (2 failed), the ASCII `YYYY-MM-DD` check removed (an ISO week date), section problems no longer voiding grants (6 failed), code spans read as comments (1 failed). After the second review, eleven more mutations each turned at least one self-test red: comment markers allowed (7 failed), HTML block starts allowed (2), HTML tags inside `## Entries` (1), escaped backticks (1), setext underlines (1), odd whitespace on fence and heading lines (2), a fence closed after any whitespace (1, through `::test_fence_and_heading_readers_follow_commonmark`), closing heading sequences allowed (3), delegated patterns refused only in the first two components (1), and either naming scheme of a support import unresolved (1 each).
- **Gate:** `tests/gates/test_deviations.py` (`::test_log_reader_grants_only_owner_approved_entries` self-test: fenced examples outside `## Entries` are not read (a shorter fence never closes a longer one), and proposed, unquoted and unknown-token entries grant nothing, not even their valid tokens; `::test_log_reader_grants_delegated_entries_only_with_quote_and_critic` self-test: an owner-approved and a valid delegated entry grant, while a delegation without the critic, with an unformed critic, without the quoted words, against a `reject`, reviewed before the delegation, reaching the template's rules or next to an owner approval, and proposed or rejected entries, grant nothing, with the exact problem of each; `::test_log_reader_voids_hidden_repeated_or_malformed_lines`, one case per way to hide, repeat or malform a line, each with its exact grants and problems; `::test_template_rule_reach_sees_paths_and_wider_patterns`; `::test_delegated_mypy_tokens_name_one_module`; `::test_fence_and_heading_readers_follow_commonmark`; `::test_template_support_files_are_named_once`, with the self-tests `::test_support_reader_follows_every_import_form` and `::test_naming_reader_reports_missing_and_extra_names`; `::test_architecture_log_is_well_formed`; `::test_escape_hatches_only_where_the_owner_approved`, over every `.py` outside dot folders; `::test_no_conftest_can_drop_a_gate`), `tests/gates/test_config.py` (also `::test_pytest_collects_every_test_folder`, `::test_pyproject_is_the_only_tool_configuration` and the exact ruff/mypy excludes), `tests/gates/test_style.py::test_every_top_level_import_is_lazy`. Reader in `tests/support/deviations.py`.
- **Does not prove:** that the quoted words were really the owner's. An agent can still forge an approval; the gate only makes forging an explicit, reviewable lie instead of a quiet edit. Nor does it catch a rule without a token (a skipped review, a JSON parser outside the decoder): those stay with the owner's review of the diff. For a delegated entry, the gate checks only the shape: not that the owner wrote the delegation, not that its words cover this decision or are still in force, not that a critic ran, was independent of the author, or checked what its line says. Those stay with the owner's review of the log. Nor does the reader model CommonMark: it follows only ATX headings and code fences, and refuses the markup that could hide or reshape a line (comments, HTML, escaped backticks, setext underlines, closing heading sequences, odd whitespace) instead of rendering it. Markup it neither follows nor refuses (a link reference definition, an indented code block before `## Entries`, lazy continuation lines) is read as plain lines, so the owner's review reads the log as text, not only rendered.

### D9. Boundaries: declared libraries only, no module loaded by name, stubs checked

- **Rule:**
  - A third-party import in `backend_logic/` or `http_adapter/` (at any depth: top level, `lazy`, inside a function or an `if TYPE_CHECKING` block) names a library that `[project] dependencies` of `pyproject.toml` declares, directly or through a requested extra (`uvicorn[standard]` grants `yaml`). An extra's requirement is granted only when its marker is exactly `extra == "<name>"`; a compound marker (`extra == "x" and sys_platform == ...`, `extra == "x" or ...`) grants nothing, because the standard library has no marker evaluator and the gate does not guess: declare that library directly. A library that is only installed is not granted: a transitive dependency (`starlette`, through `fastapi`) or a dev tool (`httpx`). An outbound adapter (guide §10) declares its client there. `tests/` is not scanned: it uses the dev group.
  - Nothing in that code can load a module, or run code, from a string. What does so is forbidden, not its call names, because a call name is dodged by an alias, a `getattr` or a library's own helper. The closed lists are in `tests/gates/test_boundaries.py`, each entry with its reason:
    - `LOADERS`: importing, or using through any name ever bound to it, a module (every submodule included) or one object of a module. Standard library: `importlib`, `_frozen_importlib`, `_frozen_importlib_external`, `_imp`, `pydoc`, `runpy`, `pkgutil`, `zipimport`, `builtins`, `modulefinder`, `doctest`, `unittest`, `logging.config`, `pickle`, `_pickle`, `shelve`, `multiprocessing.forkserver`, `optparse`, `xml.dom.domreg`, `xml.sax.make_parser`, `turtle`, `profiling`, and the modules that run a code string (`profile`, `cProfile`, `timeit`, `trace`, `pdb`, `bdb`, `code`, `codeop`). Template dependencies: `uvicorn` whole (its `run`, `Config.load`, `Server` and `main` import the app from a `"module:attr"` string; the process command line starts the server, never the code), `watchfiles.run` and its re-exports, `websockets.imports` and `websockets.lazy_import`, and PyYAML's unsafe constructor (`yaml.constructor`, `yaml.loader`, `yaml.cyaml`, `yaml.Loader`, `yaml.UnsafeLoader`, `yaml.CLoader`, `yaml.CUnsafeLoader`, `yaml.unsafe_load`, `yaml.unsafe_load_all`; `yaml.safe_load` stays allowed);
    - `sys.modules`, at any depth (`sys.modules[...]`, `from sys import modules`, `os.sys.modules`);
    - `LOADER_NAMES`: the builtins `__import__`, `__builtins__`, `__loader__`, `__spec__`, `exec`, `eval`;
    - `LOADER_ATTRIBUTES`: the loader functions and methods (`import_module`, `import_from_string`, `import_string`, `lazy_import`, `find_spec`, `module_from_spec`, `exec_module`, `load_module`, `read_module`, `set_forkserver_preload`, `find_class`, ...) as an attribute of anything the scanner cannot resolve (`holder.read_module(...)`).

    A name is bound conservatively: every value it was ever bound to counts, through imports, `x = y`, `x: T = y`, `(x := y)` and parameter defaults, propagated to a fixed point. Rebinding `sys` later (`from http_adapter import application as sys`) does not hide `runtime = sys; runtime.modules`.

    Consequence for the HTTP server: `uvicorn` is in `LOADERS` whole (`run`, `Config.load` and `main` all load "module:attr" strings), so the code never imports it. `http_adapter/serve.py` is a factory, `app_from_env()`, and the process runs it as a command, `uvicorn --factory http_adapter.serve:app_from_env --host … --port …` (`backend_harness/entrypoint.sh`; the template README for a run without Docker). The string the server loads is on that command line, outside the code the gate reads.

    The lists are audited, not only reviewed: `test_every_loader_in_reach_is_listed` scans every public module of the standard library and of the template's own distributions (`AUDITED_DISTRIBUTIONS`) for a call of the import machinery (`support/boundaries.py`, `IMPORT_CALLS`). Each module it finds must be in `LOADERS` or in `NOT_A_LOADER`, a table of the modules that call it only on a fixed name, each with its reason (`encodings` imports only `encodings.<codec>`; `fastapi.responses` only `ujson`/`orjson`). A Python or dependency upgrade that brings a new loader turns the gate red until the pipefeuille reviews it.

    There is no allowlist and no log token. A new entry in `LOADERS` or `NOT_A_LOADER` is a change to the pipefeuille (RUNBOOK, task C), never a project's. The cost: `importlib.metadata` and `importlib.resources` are not available to the code; a package reads its own files through `Path(__file__)`, and its version comes from the owner of the process.
  - Every stub under `tests/support/` (C2, recipe 4) matches the installed library:
    - classes and their bases, functions (`async` included) and annotated names exist;
    - every parameter a `def` declares has the library's name, kind (positional-only, positional-or-keyword, keyword-only) and position; a keyword-only parameter must be named in the library's signature even when the library also takes `**kwargs`; `*args`/`**kwargs` need theirs. A parameter has a default in the stub exactly when it has one in the library. The stub may leave out a parameter that has a default in the library (a positional one only from the end), and a call with only the stub's required parameters must bind against the real signature;
    - a callable of the library is declared with `def`, never as an annotated name (`load: Callable[...]` would skip the signature check), and a `Callable` annotation needs something callable;
    - a stub `@property` is not a plain method in the library (read with `inspect.getattr_static`), and a stub setter needs a property with `fset`;
    - every re-export exists in the library: `import x as x`, `from y import a as a`, and every name `__all__` lists, in every form it is written (`=`, an annotated `__all__: list[str] = ...`, `+=`, `.extend([...])`, `.append("x")`), a plain import listed there included (the forms PEP 484 makes public in a stub); `__all__` in any other form, and a star import, are reported;
    - private typing helpers (`_T = TypeVar("_T")`, `type _X = ...`) need not exist; any other statement (an `if sys.version_info` branch, a public bare assignment or `type` alias, `__all__ +=`) is reported, so no declaration reaches mypy unchecked.
- **Why:**
  - In a project born from this template, the agent loaded three libraries by name (3 files, 4 call sites of `importlib`) behind `Protocol`s. To mypy the module was a string, so a rename in the library and its `Any` both went unseen, and `disallow_any_expr` stayed green on code it had never read. The owner rejected it as a pattern, not case by case, so the gate has no exception mechanism.
  - The first version of the gate forbade the two call names only. A critic then loaded undeclared libraries with zero hits through `pydoc.locate("httpx.AsyncClient")` (standard library, typed `object`), the declared `uvicorn.importer.import_from_string(...)`, `importlib.util.find_spec` plus `module_from_spec`, `sys.modules[...]` and `getattr(importlib, ...)`. Hence the closed list of modules, not of calls.
  - An import that resolves only because the library happens to be installed passes every test and breaks wherever only the declared dependencies are installed, or when the direct dependency drops it. Reading the declaration from `pyproject.toml` and the installed metadata keeps no second list of libraries in the gates.
  - A stub replaces the library's types for mypy. A parameter the library renamed would type-check and fail only at run time; the check moves that failure into the test run. The same critic found that the first version let a stub re-export a name the library does not have (`from httpx import AsyncClient as AsyncClient` in `tomllib.pyi` made `from tomllib import AsyncClient` pass every gate and fail at run time), skip the signature through an annotated `Callable`, declare a plain method as a property, move a positional-or-keyword parameter behind `*`, rename a positional-only one and invent a keyword when the library takes `**kwargs`. It also granted an installed `pkg-bad; extra == "a" and sys_platform == "never"`. Each is now a case of a self-test.
  - A third review found `__all__: list[str] = ["AsyncClient"]` in `tomllib.pyi` re-exporting a name the library lacks (the annotated form was never read); `watchfiles.run.import_string`, `websockets.lazy_import`, `uvicorn.Config(app="pkg:attr").load()`, `_frozen_importlib` and `_frozen_importlib_external` loading by string; a flat alias map, where `from http_adapter import application as sys` made `runtime = sys; runtime.modules` invisible; and a stub dropping `= ...` on a parameter the library makes optional. Because each round found loaders the list did not name, the list became an audit.
- **Measured:** the audit reads 682 public modules (512 of the standard library of CPython 3.15.2, 170 of the template's 7 distributions) in about 1.5 s and finds 31 that call the import machinery: 22 are in `LOADERS` (18 of the standard library; 4 of the dependencies: `uvicorn.importer`, `watchfiles.run`, `websockets.imports`, `yaml.constructor`) and 9 in `NOT_A_LOADER` (7 of the standard library, `fastapi.responses` and `dotenv.main`). On a copy of the template, each mutation fails its own test of `tests/gates/test_boundaries.py` while the other eight pass:

- **Gate:** `tests/gates/test_boundaries.py::test_third_party_only_from_declared_dependencies`, `::test_no_module_is_loaded_by_name`, `::test_every_stub_matches_the_installed_library`, with the self-tests `::test_third_party_scanner_sees_every_import_form`, `::test_every_loader_in_reach_is_listed` (the audit), `::test_loader_scanner_sees_every_form` (every loader form above, a rebound name, and the uses that are not one: `sys.argv`, `os.path`, `yaml.safe_load`, an object's own `exec` or `modules`, a string), `::test_loader_audit_finds_every_caller_of_the_import_machinery` (a synthetic tree: every call form, private modules and a string skipped), `::test_dependency_reader_grants_only_what_is_declared` (synthetic `dist-info` folders, so it holds in any project) and `::test_stub_checker_reports_every_drift` (a synthetic library, a stub that matches it and reports nothing, and two stubs with every kind of drift). Readers in `tests/support/boundaries.py`.
- **Does not prove:**
  - That the import is the right library for the package, or that the dependency is wanted: declaring it in `pyproject.toml` grants the import, and adding a dependency is reviewed in the diff. The gate does not tell one package of the project from another: any declared library may be imported anywhere in the code (the inbound-transport ban of `backend_logic` is `tests/gates/test_architecture.py::test_logic_does_not_import_http`).
  - That the library is declared by its own distribution: the gate compares top-level import names, so a namespace shared by several distributions (`google` for every `google-*` package) is granted whole by declaring any one of them.
  - That a project's added dependency brings no loader: the audit reads only the template's distributions (`AUDITED_DISTRIBUTIONS`), because its tables live in a gate a project never edits. Its loaders stay with the review of the dependency, and a new loader there is reported to the pipefeuille.
  - That the audit sees every loader: it finds a module whose own source calls the import machinery, not one that reaches it through another module (`uvicorn.config` calls `uvicorn.importer`; `unittest.mock` calls `pkgutil`), nor a C extension, nor a module that runs code strings with `exec` (those were listed by hand: `timeit`, `profile`, `code`...). Private modules are not read; the private loaders are listed by hand.
  - That no module is reached by a string through an allowed module: `getattr(sys, "modules")`, `vars(sys)["modules"]`, `globals()["__builtins__"]`, a loader passed as an argument (`f(sys)`, then `m.modules` with no default), a method of an allowed object with a name not in `LOADER_ATTRIBUTES`, a plugin entry point. Those stay with review. The listed names are reserved in the code: a variable called `eval` or a method called `import_module` is reported too.
  - That a stub's types are true. The check sees names, kinds and positions, never a type: a stub that declares `int` where the library returns `str`, or where it returns `Any`, passes (C2, "Does not prove"). Nor that a stub covers the library fully: what it does not declare is a mypy error, which is the safe side. A callable whose signature the library does not expose (some C extensions), the setter of a C data descriptor, and an attribute the constructor sets are checked only for existing. Code may still import a private typing helper of a stub (`from tomllib import _T`), which fails at run time.
  - That a compound-marker requirement of an extra would be safe to grant: it is refused everywhere, so a project that needs one declares it directly.

### D10. The agent runtime layer keeps its own rules; the root gates name its one exception

- **Rule:** `backend_harness/` is the runtime layer of the agents (§10, §11.2): dsh pinned, its profile and plugins (JavaScript), shell and YAML, and a harness server (`backend_harness/server/server.py`) that is **its own uv project** (`server/pyproject.toml`, `uv.lock`, `.python-version` 3.14, ruff with the template's rule set, strict mypy without `disallow_any_expr`, pytest). It does not follow the four-file style, has no `def run` docstrings and no pipeline; it is reached by the logic only over HTTP, through the adapter of the agent-runs port, and imports neither the logic nor the HTTP adapter. Its own gates run with `backend_harness/tests/test.sh` (plugin, runner and profile tests in the image with `--network none`; the server's ruff, mypy and pytest; the shared `sql` tool's worker, typed by the server's mypy and linted by the root's ruff; the prefix rename's self-test), `tests/context.sh --check` (the controlled context) and `tests/e2e.sh` (dispatch to `completed` through an offline stand-in model). The root gates make exactly one exception for it: `pyproject.toml` `[tool.mypy] exclude` holds `^backend_harness/`, and `tests/gates/test_config.py` allows `backend_harness/server/pyproject.toml` as the only project file besides the root's (`HARNESS_PROJECT`, `HARNESS_MYPY_EXCLUDE`). The shared `sql` tool runs its DuckDB worker on the server's venv, so the layer keeps that one project: no second exception.
- **Why:** the runtime layer is a different kind of program. Its server parses JSON from dsh and from requests with the standard library and FastAPI's models, which carry `Any`; containing that under `disallow_any_expr` would mean a boundary package per call, for no reader. It needs Python 3.14 (`compression.zstd`, to read dsh's session logs) where the logic is on 3.15. The plugins are JavaScript loaded by dsh. Forcing the four-file style on it would hide, not show, what it does. Keeping the exception narrow and named in a gate (instead of a dot folder or a glob) means a second nested project (a service, a plugin's own Python) fails the gate until it is decided, which is how the `sql` tool came back without one.
- **Measured:** on a copy of the template with `backend_harness/` and no exception, `mypy .` reported 274 errors (the server under 3.15 and `disallow_any_expr`) and `test_pyproject_is_the_only_tool_configuration` failed; with the exception, every root gate passed. The scanner's self-test refuses `backend_harness/server/ruff.toml`, `backend_harness/services/x/pyproject.toml` and `backend_logic/pyproject.toml`.
- **Gate:** `tests/gates/test_config.py::test_pyproject_is_the_only_tool_configuration` with its self-test `::test_parallel_config_scanner_allows_only_the_harness_server`, and the exact mypy excludes there; the layer's own `backend_harness/tests/test.sh`, `context.sh --check`, `context-selftest.sh` and `e2e.sh` (Docker, offline).
- **Does not prove:** that the layer's own gates run: they need Docker and are not part of the root `pytest`; a change to `backend_harness/` is checked only when someone runs them (RUNBOOK C). Nor that a real model behaves: no gate calls a provider.

## E. The architecture documents itself

### E1. The `def run` docstring: a summary and closed sections

- **Rule:** every `def run` has a Google-style docstring. The first line is the summary of the package; free paragraphs may follow. A process then declares, in this order, `Effects:`, `Repeat:`, `Loops:`, `Concurrency:` and optionally `Raises:`. Each line of a section is `<value>` or `<value>: <note>`, and the value must be a member of the enums in `tests/support/architecture.py`:
  - `Effects` (one or more): `pure` (only alone), `reads`, `writes`, `network`, `model`, `time`;
  - `Repeat` (exactly one, the worst case over the requests it serves): `safe`, `overwrites`, `fails`, `accumulates`;
  - `Loops` (exactly one, about the body of `run`): `none`, `over-items`, `capped` (note required: the limit);
  - `Concurrency` (exactly one): `free`, `locks-inside`, `caller-locks` (note required: which lock);
  - `Raises`: exception names a caller may need to handle.

  A family declares only its summary: its effects and repeat are derived from its cases. The enums are not edited in a project; a new value is a change to the pipefeuille (RUNBOOK, task C).
- **Why:** the owner wanted the architecture read as a diagram that a tool generates, not as a tree written by hand in the README, and wanted what the tree cannot show: whether a package writes, calls a model, may be repeated, takes a lock or loops. Free text would let each model improvise its own words ("idempotent-ish", "mostly pure"); a closed set, checked by a test, does not. Everything the code already shows (children and their order, `match` cases, `TaskGroup`, `async with`, loops, ports, `NotImplementedError`) is derived, never declared, so there is no second source of truth.
- **Cross-checks against the code:** `pure` ⇒ no keyword-only port and `Repeat: safe`; `Loops: none` ⇔ no `for`/`while`/comprehension in `run`; `over-items` forbids a `while`, `capped` needs one; `locks-inside` ⇔ `async with <alias>.run(...)` in `run`; a process declares every non-pure effect of the packages it calls; every `*Error` its own `contracts.py` defines is in `Raises`, and every name in `Raises` is a builtin exception or is defined in some `contracts.py`.
- **Measured:** on a copy, each of nine mutations failed exactly one gate (three for a reintroduced `__init__.py`): a value outside the enum, an invented section, a `for` under `Loops: none`, the lock of `save` declared `free`, `pure` on a package with a port, a contract error removed from `Raises`, an `__init__.py` put back, an enum member added, a docstring removed.
- **Gate:** `tests/gates/test_architecture_graph.py::test_every_run_docstring_uses_only_the_closed_vocabulary`, `::test_the_closed_vocabulary_is_the_template_one` (pins the enum values), with the self-tests `::test_graph_scanner_reports_every_violation` and `::test_docstring_parser_keeps_notes_and_continuations`.
- **Does not prove:** that a declared value tells the truth where the code cannot be read: `Repeat`, `reads` against `writes`, `network`, `time` and the notes stay with the orchestrator's review. The cross-check of effects only climbs through calls the graph sees (`<alias>.run(...)`).

### E2. The graph is generated from the code

- **Rule:** `uv run python tests/support/architecture.py` prints the use-case tree, then one shelf per `_shared/`, each package with its kind, effects, repeat, loops and concurrency, and the **steps of its `run`** in order: the Pipe methods and direct `<alias>.run(...)` calls, inside the frames of the code (lock, branch, match, loop, `TaskGroup`, try), each with the packages it calls. A call is `per-item` when it repeats over a collection, in `run` or inside the method (so `Loops:`, about `run` only, is not contradicted), and `lock`/`parallel` from its frame. `--json` prints the whole graph with the steps; `--html <file>` writes a self-contained page (HTML, no network): the use-case tree on the left, the `_shared/` shelves apart (never arrows across the tree; a package shows what it takes from outside its children as chips), and a panel with the steps and the docstring of the selected package; a Tree / Graph toggle also draws every call at once (columns by depth, shelves in bands, pan and zoom). Generate the page under `.dumps/`; it is not versioned. The tool also lists **alerts**: a `per-item` call into a package whose `Repeat` is not `safe`. An alert does not fail a gate; it asks the reader to confirm that the repetition is intended (in the template, `roles/digest` → `roles/summarizer`: one model call per note, by design).
- **Why:** a tree written by hand in the README goes stale at the first new package. The agent that needs the map calls the tool and gets the current one; the human gets a diagram that is always complete.
- **Why this layout:** a first version drew every call as an arrow over the folder tree. Shared packages sit far from their users, so `save` alone sent six arrows across the page, ordered by file instead of by step, and a loop inside a method showed on the edge while the node said `Loops: none`. The tree of use cases is the reading path; what is shared is a different question (who takes what) and is answered apart; the order is the one of `run`.
- **Gate:** `tests/gates/test_architecture_graph.py::test_every_package_is_reached_from_the_root` (a package no call reaches is dead code or a call the graph cannot see), `::test_every_call_is_made_by_a_step_of_run` (an imported `run` that no step reaches would be missing from the story), `::test_step_reader_follows_run_in_order_inside_its_frames` (self-test: chain, guard left out, lock, branch, `TaskGroup` with a loop, a per-item call through a helper, an unused import reported), `::test_the_page_shows_every_node_and_edge` (every node has a card and a panel, every edge an element; no `http://`/`https://`). Verified by eye in a browser: tree, shelves, chips, step panel, graph view (trace on hover, selection), no console errors.
- **Does not prove:** calls made other than through `<alias>.run(...)`; that a step's label tells more than its method name (the method docstring does); the page's readability for a much larger tree.

## F. Developer tools

### F1. Agent sessions are read with `tools/telemetry`, a developer tool no product agent gets

- **Rule:** `tools/telemetry/` (`app-telemetry`, Node) is the one reader of the dsh session logs that `backend_harness/` agents write: a terminal UI (sessions list, then the vendored dsh-tui Trajectory screen) and headless JSON lines (`sessions`, `trajectory`, `sync`, `schema`, `sql`) over a local DuckDB cache of feature tables. Sources are only `--local` (the running `app-harness-local` container of `backend_harness/docker.sh`, copied with `docker cp`) and `--dir PATH`; nothing is ever written to a source. Every query goes through one guard, `query` in `tools/telemetry/src/db.js`: a private read-only copy per query, `enable_external_access = false`, extension autoinstall and autoload off, `lock_configuration = true`, only `SELECT`/`EXPLAIN` statement types after every statement is prepared, then DuckDB's parse tree of the query (`json_serialize_sql`) searched for the logging table functions and `query`/`query_table`, refusing what cannot be serialized. Its dsh plugin `dsh-plugin-app-telemetry-sql` (`telemetry_sql`, `telemetry_schema`) reuses that guard, takes a cache by name only, never by path, and is installed only in the developer's own dsh profile. Nothing in `backend_harness/` that reaches an agent (image, profiles, `agent.yml`, `docker.sh`) names the tool. Its names carry the harness prefix, and `backend_harness/rename-prefix.sh` renames both.
- **Why:** a session log holds one zstd frame per append, and node's decoders stop after the first frame: decoding by hand silently loses every turn after the first. A model that reads telemetry with a general SQL engine can write files, read the machine or attach other databases unless a guard says otherwise. The source's check of the logging functions was a regular expression on the text: `"enable_logging"(...)`, a comment before the parenthesis, or the same call assembled inside `query('...')` passed it and ran (found by attacking it during this backport); a name is now matched on the parse tree, never the text. And a tool that reads every tenant's runs, given to a product agent, would hand that agent other tenants' data. Owner decision (2026-11-17): only generic sources (no cloud object store), and a developer tool that product agents never get.
- **Measured:** on real sessions of the template harness (the example agent under the offline stub model), the whole cycle runs: `--local sessions`, `trajectory`, `sync`, `schema`, `sql`. Each of four mutations of the guard turns its refusal tests red: statement-type check removed (7 tests), external access left on (3), extension autoload left on (3), parse-tree function check removed (4). The plugin, booted by the pinned dsh in a throwaway harness container, answers 2 reads and returns 5 refusals as tool errors (`test/dsh-boot.sh`). A renamed copy (`rename-prefix.sh zq`) passes the tool's 64 tests.
- **Gate:** the tool's own `npm test`: `test/refusals.js` (writes; file reads and writes; settings changes; other databases and extensions) run against `sql` (`test/db.test.js`) and the plugin (`test/plugin.test.js`), with the cache file checked byte for byte; `test/placement.test.js` (nothing in `backend_harness/` but docs, its `tests/` and `rename-prefix.sh` names the tool), with its self-test on a synthetic tree; `test/plugin.test.js::the plugin never imports sources.js`. `test/dsh-boot.sh` (docker, the harness image) for the plugin inside dsh. `backend_harness/rename-prefix.sh --self-test` for the shared prefix. The template's Python gates do not read the folder (no Python; `test_pyproject_is_the_only_tool_configuration` scans it, and `node_modules/` holds no tool configuration today).
- **Does not prove:** that the guard stops every way DuckDB has to reach outside, beyond the listed refusals and DuckDB's own settings; a DuckDB upgrade must rerun the refusals. That a developer's profile does not insert the plugin into a product profile by hand: the placement test reads only `backend_harness/`. That the TUI draws correctly on every terminal (its tests render one 140x36 screen). The fixtures are two sessions of one example agent; sessions with failed runs, subagents or other providers are not among them. The vendored dsh-tui third-party notice is kept whole because it does not list which files it covers.
